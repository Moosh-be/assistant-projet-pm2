# WP-0035 — Fil pédagogique des abréviations

## Contexte
Feedback 1 (10/11) : le lecteur (d'un artefact ou d'un échange) ne connaît pas
forcément les abréviations. Deux niveaux :
1. **Lecture** : 1re occurrence = **nom complet (abréviation)** — dans les docs
   comme dans les échanges.
2. **Assimilation conversationnelle** : l'interlocuteur assimile une abréviation
   quand **il** l'a utilisée **3 fois** dans les échanges (ou l'a demandée
   explicitement) → statut noté dans le registre ; **assimilée = l'abréviation
   seule peut être utilisée avec lui**.

État initial (10/11) : décision consignée + registre
`_meta/registry/abreviations.md` initialisé (RfP / WP / IA notées « assimilées
`[À confirmer]` » — comptage de l'assistant à valider par l'interlocuteur).

## Brouillon de périmètre (à raffiner)
- [ ] Règle dans `AGENT-projet.md` (« La voix » ou nouvelle section « Pédagogie ») :
      1re occurrence = nom complet (abréviation) ; si l'abréviation est marquée
      « assimilée » dans `registry/abreviations.md` → l'abréviation seule est
      autorisée dans les échanges avec cet interlocuteur.
- [ ] Comptage des usages : **qui** compte (l'assistant, en fin de session ?) et
      où est noté le 3e usage (suggestion : la colonne `source` du registre cite
      les occurrences).
- [ ] Application aux artefacts et docs existants : passer en revue templates PM²
      et README/prise-en-main pour introduire les abréviations à la 1re
      occurrence (RfP/RfE/RfC, BM/CP/MOE, SPO/QAM, WP, PM²…).
- [ ] SPO / QAM : **expansions officielles à confirmer** — le kit ne glossifie
      que « méthodologue » / « qualité ».

## Ouvert (à trancher avec l'utilisateur)
- Le registre est-il **par projet** (chaque `_meta/registry/`) ou **par
  interlocuteur** (transposé entre projets) ?
- « 3 fois » : usages dans les messages de l'interlocuteur uniquement (pas les
  citations de lui faites par l'assistant) ?
