# Cas d'usage (business case)

> **Template** : 02.I · **Phase** : 01 Lancement · **Gate** : RfP
> Ce document est un **squelette générique** (contribution PM², v3.0.1). Le fork RTBF
> enrichit chaque champ avec la traduction RTBF du template Word d'origine.

## 1. Contenu

### 1. Contexte et problème

Mener un projet (Lancement → Clôture) repose sur la mémoire de chacun et des
documents éparpillés. La méthode PM² existe (templates, gates) mais il n'y a pas
de **squelette prêt à l'emploi** avec un assistant IA qui pose les bonnes
questions au bon moment et garde la traçabilité.
L'expérimentation est **mandatée** (06/11 : « on m'a demandé de consacrer du temps »)
et suit des instances existantes : comités **IA**, réunions **PMO**, réunions **COP Projet**.
(source : `_meta/fiche.md` §1 + `_meta/registry/decisions.md` + session du 06/11)

### 2. Options considérées

- **(a) Fork RTBF privé** seul — hors périmètre du repo public (pas de données entreprise).
- **(b) Solution/kit open source avec modularité** + un **fork « configuré » pour le contexte RTBF** en dérivé. Confirmé 06/11 : « l'idée est bien une solution / kit opensource, avec de la modularité, et un fork "configuré" pour le contexte rtbf ».
(source : session du 06/11 + `_meta/fiche.md` §1 « Hors périmètre »)

### 3. Option retenue et pourquoi

**(b)** : kit open source (FR) + protocole `AGENT-projet.md`, **modulaire**
(1 projet = 1 folder), zéro infrastructure, compatible avec n'importe quel
harness IA. Le fork « configuré » RTBF est le **dérivé** prévu, hors périmètre
du repo public.
(source : session du 06/11)

### 4. Estimation de la valeur (bénéfices)

- **Utilisable pour tous** (GitHub) et **pour la RTBF** (GitLab) — même kit, 2 contextes.
- **Utilisé** — sans obligation (l'adoption se joue sur le terrain, 06/11).
- Gain de temps à la constitution de chaque projet ; moins d'oublis (1 gate = 1 checklist) ;
  traçabilité « rempli par la preuve ».
Valeur **qualitative** — aucune estimation quantitative fournie (06/11).

### 5. Estimation du coût

- **Temps** : du porteur + des **challengers** ; bonus : temps pour de l'aide.
- **IA** : budget token sur l'IA interne + éventuellement module **Copilot Pro**.
Pas d'enveloppe monétaire dédiée.
(source : session du 06/11)

### 6. Hypothèses et dépendances

- Méthode **PM² v3.0.1** publique comme référentiel de templates.
- Fichiers Markdown génériques, lisibles par n'importe quelle IA.
- Harness : OpenCode (sessions, slash-commands `/ap-*`) — le kit ne dépend d'aucun outil spécifique (source : `decisions.md`, préfixe 04/11).
- Contrainte : repo **public** → pas de données entreprise ; le fork RTBF (GitLab) est un dérivé configuré, **hors de ce repo**.
- Des **challengers** seront mobilisés (rôle exact à confirmer). `[À confirmer]` (06/11)
- Suivi via comités IA / PMO / COP Projet (dates à recenser).
